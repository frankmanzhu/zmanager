# ZManager CLI 2.1.2 Release Notes

ZManager CLI 2.1.2 is a maintenance release that fixes broken UniFFI bindings shipped in 2.1.1, types more of the mobile-facing FFI surface, and hardens CI so a bindings/source mismatch can't ship again.

## Highlights

### 🛠️ UniFFI Bindings Fix
- **Regenerated Swift/Kotlin Bindings**: 2.1.1's checked-in bindings still referenced `localsend_*_json` passthrough functions that had already been replaced by typed FFI functions before that tag was cut, breaking the link step for any native consumer (including zmanager-desktop's macOS target). Bindings are now regenerated against current source.
- **CI Staleness Gate**: Added a `uniffi-bindings-check` CI job that regenerates bindings into a scratch directory and diffs them against the checked-in copy, failing the build if they've drifted — the class of bug that caused 2.1.1's break can no longer reach `main` unnoticed.

### 📱 Typed Mobile FFI Surface
Continuing the mobile-code-health remediation track, more of the JSON-passthrough FFI boundary used by zmanager-mobile is now typed:
- **TZAP Identity**: The seven `tzap_*_json` functions zmanager-mobile actually calls (`tzapAuthLogin`, `tzapAuthCallback`, `tzapAuthStatus`, `tzapCertificateInventory`, `tzapCertEnroll`, `tzapDocumentSign`, `tzapDocumentVerify`) are now typed against dedicated UDL dictionaries instead of passing raw JSON.
- **LocalSend Trust Store**: Trusted-fingerprint persistence (previously hand-rolled independently in Android `SharedPreferences` and iOS `UserDefaults`) now lives in a single shared implementation (`trustIsTrusted`/`trustRemember`/`trustForget`/`trustFingerprints`) owning the file schema, sort order, and atomic-write discipline.
- **Recovery Records**: Recovery-record persistence and the 7-day retention window are now shared across platforms (`recoverySave`/`recoveryRecords`/`recoveryDiscard`/`recoveryFiles`) instead of being reimplemented per-platform with divergent units (millis vs. seconds) and cleanup behavior.

## Upgrading

Consumers pinning a `zmanager-core` / `zmanager-ffi` git tag should move from `v2.1.1` to `v2.1.2` to pick up the corrected bindings. No API-breaking changes for CLI users.

## Installation

### macOS (Homebrew)
```sh
# Full build
brew install tzap-org/zmanager/zmanager

# Offline build (no network features)
brew install tzap-org/zmanager/zmanager-offline
```

### Linux (Install Script)
```sh
# Full build
curl -fsSL https://raw.githubusercontent.com/tzap-org/zmanager/main/install.sh | sh

# Offline build
curl -fsSL https://raw.githubusercontent.com/tzap-org/zmanager/main/install.sh | sh -s -- --offline
```

### Windows (WinGet)
```powershell
# Full build
winget install TzapOrg.ZManagerCLI

# Offline build
winget install TzapOrg.ZManagerCLI.Offline
```
